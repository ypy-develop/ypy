# Changelog

## 0.1.1

Fixes found when the framework was adopted by the Arandu modules (TASK-096). The tag `v0.1.0` published a build whose `ypy.version` said `0.1.0-dev`.

- One version, written once. The file `VERSION` at the root is the source: `ypy build` stamps it into `ypy.version` (`dist/ypy.js`, the minified and ES module files and `ypy.max`), `ypy gen` writes it into the JetBrains web-types, and `ypy --version` reads it with `go:embed`. `src/attributes.json` no longer has a `version` field. A Go test fails when `VERSION`, `src/ypy.js`, the web-types or `dist/` disagree. `dist/ypy.min.js` reports `0.1.1`.
- The order of `ypy:after:swap` and `ypy:after:settle` is documented as it is: `ypy:after:settle` fires for each swapped target (main, out-of-band, partial) after it was inserted, and the new content is processed; `ypy:after:swap` fires once, after every target settled. The guide of events had them the other way round (swap at step 8, settle at step 9); it now lists the real order, and a test fixes it. Moving `ypy:after:swap` before the settle would make it fire once per target, which changes its meaning and does not fit the 18 kB of the core.
- `ypy:before:cleanup` and `ypy:after:cleanup` reach only elements YPY processed (with a `ypy-*` or `data-ypy-*` attribute). The attribute table, `ypy.d.ts` and the events guide say so and point to a `MutationObserver` for the other elements; a test covers both cases.
- Source maps: the `.min.js` of `dist/` keep their `//# sourceMappingURL` comment and `.map` (a CDN serves them), and the build now writes the same code without the comment under `dist/embed/` (`ypy.min.js`, `ypy.esm.min.js`, `ypy.max.min.js`, `ext/*.min.js`) for whoever embeds only the script and would otherwise see a 404 for the map in DevTools. See the README ("Source maps").

## Unreleased

- The e2e suite runs in Chrome, Firefox and Safari (TASK-092). `internal/e2e` talks to the browser through a `Driver` interface with two implementations, DevTools (Chrome) and WebDriver (Firefox and Safari, over `internal/browsers`); `ypy test --suite e2e --browsers chrome,firefox,safari` works, and the `e2e` gate of `ypy ci` uses the browsers of the `browser` gate. A scenario is registered with `Register` from a file of its own (see the top of `internal/e2e/scenarios.go`) and can say `Skip` for a browser, with the reason. The 19 scenarios pass in the three browsers.
- End to end SSR and SPA (TASK-093). The example server serves a small server-rendered site (`/ssr/`, and `/ssr-nojs/` with a CSP that forbids scripts) and 19 scenarios run on it in any browser: the same URL answers a page or a fragment with `Vary: YPY-Request`, a refresh or a history restore gets the whole page, forms with 422 and 303, pages without scripts, global boost, current link, back and forward, focus on the title, `ypy-persist`, progress bar, prefetch, a response from outside the app, and an edit saved before leaving. Two defects found and fixed: after a boosted navigation that replaces the link itself, the focus did not move to the new heading and the title was not announced (the source element had become the swap target, which is not boosted); and a click on a link did not wait for the save started by the change of the field it had just blurred (`ypy-nav` only looked at the field that still had the focus).
- New extension `ypy-native` (ADR-0017): the web side of the native app bridge. A shell hosts the same server-rendered pages in a web view and owns the navigation; the extension sends `YPY-Native: <platform>; v=<n>; caps=<list>` on every same-origin request after a handshake over `window.ypyNative`, sets `data-ypy-native` on the root, hands boosted navigation (`visit`), `YPY-Location` and a redirect after a post to the shell, keeps the page from writing history, mirrors the title and address, and connects `ypy-native-component` elements (`ypy-native-props`, `ypy-native-hide`, `ypy-native-only`, `ypy-native-click`) to native components the app lists. The path configuration lives at `/.well-known/ypy-native.json`; a route with `presentation: none` stays in the page, and with `config.native.web` a `context: modal` route opens as a layer in a browser. Not in `ypy.max`; 2.8 kB min+gzip; the core did not grow. New protocol header `YPY-Native`, events `ypy:native:event`, `ypy:native:before:visit` and `ypy:native:navigate`, skill `ypy-native`.
- Streaming of model answers into fragments (ADR-0018, TASK-090). New extension `ypy-model` (in `ypy.max`): `ypy-untrusted` strips scripts, forms, frames, svg, `ypy-*`, `data-ypy-*`, `on*` and bad addresses from what enters a container written by a model; announcements at the start and the end of an answer (`ypy-announce-start`, `ypy-announce-stop`, `ypy-announce-error`, `config.announce.messages.answer*`, and the opt-in `config.announce.stream: "blocks"`); `ypy-follow` (scroll with the answer for a reader at the bottom); `ypy-stop` (a Stop button). `ypy-stream` merges waiting patches of one selector (`inner`/`outer` keep the last, `append` concatenates; `stream.merge`, on), can apply events one animation frame apart (`stream.frame`, off) and closes on `ypy:abort`. The protocol gains the optional merge rule (5.3) and the recipe (5.8), with the conformance vectors `model-*`.
- Safari (TASK-091): a history write the browser refuses (Safari throws a `SecurityError` past 100 writes in 10 seconds) no longer breaks a swap: the core, `ypy-layers`, `ypy-history-cache` and `ypy-browser-indicator` catch it, the URL stays, and `ypy:after:history:push` / `ypy:after:history:replace` fire only for a write that happened. `ypy-layers` keeps the focus inside a modal with a `focusin` guard, because Safari makes the page behind inert only after the next render. The core grew by about 15 B (18394 of 18432 B min+gzip). The main suite passes in Chrome, Firefox and Safari; the `ext` and `security` suites pass against `dist/` in Safari; the e2e suite then only drove Chrome (see TASK-092).
- `ypy-disable` and `ypy-inert` (disabling elements and making the target inert while a request runs, `config.inert`) moved out of the core into the new extension `ypy-disable`, which `ypy.max` includes, so `ypy.max` behaves as before; with `ypy.min` load `dist/ext/ypy-disable.min.js` to keep them. This frees core room for TASK-084 (the core is now 18286 B min+gzip of 18432). `ypy gen` no longer warns about hooks that only extensions receive, such as `ypy_resolve_target`.
- `ypy-signals` sends the signals only when asked: `ypy-signals-send` on the element (or `ypy-signals-send:inherited` on a container) or `ypy.config.signals.send: true`. Signals whose name starts with `_` are never sent.
- Morph and focus after a swap (TASK-084). A morph no longer merges the children of a custom element that is already defined (`customElements.get`): only its attributes follow the response, unless the response marks it with `ypy-morph-force` or it carries `ypy-preserve="false"`. The swap no longer focuses the `[autofocus]` element of swapped content (that broke web components that manage their own focus) unless the element carries `ypy-focus` or `config.autofocus` is on. `ypy-focus="auto"` after a boosted navigation now falls back to the swap target when the page has no main, and the live region no longer says the title again when the focus moved to a heading or main (`ctx.focused`). New extension `ypy-preserve` (in `ypy.max`): `ypy-preserve="value selection focus scroll"` keeps one state of an element through a morph and through a raw swap, and a swap waits for the end of an IME composition in a field its target contains (`config.compositionTimeout`, 3000 ms). The core gains the hook `ctx.hold`. The core grew by about 93 B (min+gzip, as the size gate measures it).
- `ypy migrate` converts a project written before YPY directly to YPY (`dist/ypy.min.js`), and `ypy check` lists what behaves differently. The migration guide, the `ypy migrate` and `ypy check` guides and the recipes (Arandu included) describe that path. ADR-0002 is Superseded by.
- YPY: a hypermedia-oriented JavaScript framework. Any HTML element can issue an HTTP request and swap the HTML fragment the server returns into the page.
- One global object, `ypy`. Events are `ypy:*`, extension hooks are `ypy_*`, the configuration meta tag is `ypy-config`, and the state classes are `ypy-request`, `ypy-swapping`, `ypy-settling`, `ypy-added` and `ypy-indicator` (configurable through `ypy.config.classes`).
- One set of names: `ypy-*` and `data-ypy-*` attributes (when an element carries both, `ypy-*` wins), the `<ypy-partial>` tag, `YPY-*` HTTP headers for requests and responses, and extensions named `ypy-<name>`: the file `src/ext/ypy-<name>.js` registers `ypy-<name>`, which is the name `config.extensions` lists (the old short names such as `sse` or `preload` are not accepted; `ypy migrate` rewrites them). Projects written before YPY are converted by `ypy migrate`.
- Distribution files: `dist/ypy.js`, `dist/ypy.esm.js`, `dist/ypy.min.js`, `dist/ypy.esm.min.js`, `dist/ypy.max.min.js`, `dist/ypy.d.ts`, `dist/ext/*`.
- Faster attribute lookup: an attribute read tests two spellings (`ypy-` and `data-ypy-`) instead of four, the spellings of each name are cached per prefix list, selectors are cached, and elements without attributes are skipped. `config.prefix` (default `""`) adds one custom prefix after them. The parsed response headers are `ctx.ypy`.
- Editor support: `ypy gen` generates the VS Code HTML Custom Data (`editors/vscode/ypy.html-data.json`), the JetBrains web-types and the JSON Schema of the `ypy-config` meta tag from one table of names (`src/attributes.json`, plus one fragment per extension in `src/attributes.d/`). `ypy gen --check` is the `gen` gate of `ypy ci`: it fails when a generated file is stale, when `ypy.d.ts` and the table disagree on events and config keys, or when a source uses a name the table lacks. See https://ypy.dev/docs/reference/editors.
- `ypy.d.ts` covers every event and config key of the core and of the extensions (`ypy-sse`, `ypy-ws`, `ypy-multipart`, `ypy-signals`, `ypy-history-cache`, `ypy-head`, `ypy-download`, `ypy-prompt`, `ypy-preload`). Extension hooks that never reach the DOM are in `YpyHookMap`, not in `YpyEventMap`; `ypy.config.lock` is optional because `ypy-lock` adds it.
- Security fixes of the 2026-11-15 audit (the security audit of 2026-11-15, section "Fixes", on https://ypy.dev/docs/security/audit-2026-11-15): the nonce gate reads the response nonce from the header only and vetoes unnonced out-of-band elements and partials (new extension hook `ypy:before:oob`); a redirect header and a multipart redirect follow only http(s) URLs of the page's origin; `ypy-ws`, `ypy-preload` and `ypy-download` keep to the request pin; `allowEval:false` means `callbacks:"none"`, `ypy-vars` obeys `callbacks`; `allowScriptTags:false` works; `ypy-head` merges the head of full documents only; `ypy-history-cache` skips sensitive fields and has `ypy.history.clear()`; `HCON.split` and the head extraction are linear. The tools do not follow symlinks out of their directories, the test server serves only the test files to `localhost`, and the toolchain is pinned to go1.26.11.
- License: MIT.
- Development extensions `ypy-dev` and `ypy-inspector` (not in `ypy.max`; development only). `ypy-dev`: errors with context for a missing target, an unknown swap style, an empty response, a 4xx or 5xx response and a timeout; `ypy.dev.latency()` and `ypy.dev.offline()`; warnings for an unknown attribute (with a suggestion), an attribute that is not inherited without `:inherited`, a `ypy-target` that matches nothing, `ypy-on` with `callbacks:"none"`, `ypy-`/`data-ypy-` conflicts and markup written before YPY (with a link to the guide); reload of templates through a Server-Sent Events endpoint. `ypy-inspector`: a floating panel (Shadow DOM, no inline style) for requests, swaps, events with origin and destination, signals and stream events, with a filter, pause and JSON export. See https://ypy.dev/docs/reference/dev and https://ypy.dev/docs/reference/inspector.
- `ypy-retry` modes: `on:network` (default), `on:error` (also 5xx), `on:always` (also 4xx) and `on:never`, in the attribute or `ypy.config.retry.on`; random `jitter` on the backoff (`jitter:0.2` or `20%`, off unless set); a 503 or 429 that is repeated waits at least its `Retry-After`. `ypy:request:retry` has the new `status`. `ypy-dev`: an error overlay (`dev.overlay`, on by default only on a development host), warnings when `ypy-sync` aborts or drops a POST, PUT, PATCH or DELETE, and a message for 401, 403 and 419 that points at an expired session or CSRF.
- Start-up and targets (TASK-077). Trigger filters take nested brackets and quoted brackets (`click[a[0]]`, `keyup[key=='[']`, four levels deep); a second `<script>` keeps the first instance and warns (`ypy: loaded twice`); `parent` and `self` are targets (`ypy-target="parent"`); the internal API has `initEvaluator`, the hook an extension uses to run author code without `eval`. New extension `ypy-expr` (2.7 kB): trigger filters, `ypy-on` and `js:` values run without `eval` or `new Function`, so they work under a CSP without `unsafe-eval` (`config.callbacks` still decides whether author code runs; it is not in `ypy.max` because it replaces the compiler of every piece of author code). New extension `ypy-boot` (load it first): `requires`, `provides` and `version` in `registerExtension()` and `ypy.supports('expr@1')`, the `ypy:ready` event after the first process, `ypy-ignore` set on a processed element tears it down, and the focus follows the `#fragment` of a request. What did not fit the 18 kB core and stays open: the target `scope`, slot-aware and nested shadow root search, and the dependency check inside the core.
